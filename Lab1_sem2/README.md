## Кратко о задаче

Нужно реализовать информационно-поисковую систему (ИПС) с **логической (Boolean) моделью** поиска по коллекции англоязычных текстов, пользовательский интерфейс (в т.ч. для работы в локальной сети) и программный расчёт метрик качества (ROMIP).

Логическая модель: документ — множество терминов, запрос — выражение с операторами `AND` / `OR` / `NOT`. Поиск выполняется через **инвертированный индекс** (термин → список документов).

Веса терминов считаются по формулам из методички:

- \( B_i = \log(N / P_i) \) — инверсная частота термина (1.5)  
- \( A_j = Q_j \times B_i \) — вес термина в документе (1.6)

## Возможности системы

### Поиск (Boolean)

- Операторы: **AND**, **OR**, **NOT**
- Токенизация английского текста, удаление стоп-слов
- Инвертированный индекс в памяти (перестраивается при изменении коллекции)
- В выдаче:
  - активная ссылка на документ
  - фрагмент текста (snippet)
  - список слов запроса, найденных в документе
  - веса совпавших терминов \( Q \cdot B \)

Примеры запросов:

```
artificial AND intelligence
machine OR learning
network AND protocol
ai AND learning NOT network
deep learning AND neural
```

### Хранение документов

| Файл | Роль |
|------|------|
| `data/documents.db` | основная БД (SQLite) |
| `data/documents.json` | снимок коллекции (обновляется при изменениях) |

Таблица:

```sql
documents (
  id    INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  text  TEXT NOT NULL,
  date  TEXT
)
```

### Загрузка документов (раздел «Загрузка»)

1. Добавление текста вручную (заголовок + текст)
2. Загрузка файла `.txt`
3. Импорт JSON-коллекции
4. Удаление документа из базы

После любого изменения индекс перестраивается автоматически.

Формат JSON для импорта:

```json
{
  "1": {
    "title": "Document title",
    "text": "Full text in English...",
    "date": "2025-03-12"
  }
}
```

### Элементы ИИ: интерфейс с пользователем (вариант 7)

По варианту акцент на интеллектуальном интерфейсе:

| Функция | Описание |
|---------|----------|
| **Автодополнение** | подсказки терминов из словаря индекса при вводе (`/api/suggest`) |
| **Подсветка** | слова запроса выделяются в сниппетах |
| **Связанные термины** | слова, часто встречающиеся в тех же документах, что и запрос |
| **Примеры запросов** | генерируются по частотным терминам коллекции |
| **Веса терминов** | отображаются в выдаче и на странице документа |

### Метрики качества (ROMIP)

Считаются программно по тестовым запросам и экспертным оценкам релевантности (`RELEVANCE_JUDGMENTS` в `data/collection.py`):

| Метрика | Смысл |
|---------|--------|
| **Precision (P)** | доля релевантных среди найденных |
| **Recall (R)** | доля найденных среди всех релевантных |
| **F1** | гармоническое среднее P и R |
| **P@5, P@10** | точность на первых 5 / 10 документах |
| **AP** | average precision |
| **R-Precision** | precision на уровне R (число релевантных) |

На странице «Метрики» — таблица и графики (Chart.js).

## Основные модули (как устроено)

1. **`models/document.py`** — токенизация (`[a-z]+`), стоп-слова, частоты терминов в документе.
2. **`models/index.py`** — инвертированный индекс `term → {doc_id}`; `idf()`, `term_weight()` по формулам (1.5)–(1.6).
3. **`models/search.py`** — разбор запроса, операции над postings-множествами, формирование выдачи.
4. **`models/metrics.py`** — расчёт метрик по списку найденных id и qrels.
5. **`models/storage.py`** — CRUD в SQLite, импорт/экспорт JSON.
6. **`models/interface_ai.py`** — подсказки, подсветка, связанные термины, примеры запросов.
7. **`app.py`** — маршруты Flask, пересборка индекса при загрузке документов.

## Замечания

- Ранжирования нет: в Boolean-модели все найденные документы равноправны.
- Стемминг/лемматизация не используются (слова `learn` и `learning` различаются).
- Метрики осмысленны для фиксированного набора qrels; после сильного изменения коллекции оценки релевантности нужно обновлять вручную в `data/collection.py`.
